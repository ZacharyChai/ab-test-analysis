# Landing-page A/B test — did the new page lift conversion?

A full read of a classic landing-page experiment (Udacity "Analyze A/B Test
Results" dataset: 294,478 page views, Jan 2–24 2017, users randomised to the old
or new page with a binary `converted` outcome). The point isn't the two-
proportion test — it's the checks around it that decide whether that test's
number can be trusted: sample-ratio mismatch, power, novelty/primacy,
segment reversals, and a guardrail.

**Recommendation: do not ship the new page.** Conversion was 12.04% (control) vs
11.88% (treatment) — an absolute lift of **−0.16 pp** (95% CI −0.39 to +0.08),
z = −1.31, **p = 0.19**. There is no evidence the new page helps, the point
estimate is slightly negative, and the test had enough traffic to detect a lift
one-quarter the size of what the team would have cared about. Keep the old page.

## How the result holds up to scrutiny

| Check | Finding | So what |
|---|---|---|
| **Data cleaning** | 3,893 rows (1.3%) had `group`/`landing_page` disagreeing; 1 duplicate user. Dropped → 290,584 clean. | Cleaning is reported, not silent. |
| **Sample ratio mismatch** | 145,274 vs 145,310; χ² p = **0.95** | Randomisation is intact — downstream numbers mean something. Run *before* looking at conversion. |
| **Power** | ~145k/arm supports a detectable effect of **±0.34 pp** at 80% power, vs the pre-registered ±0.6 pp of interest. | This is a genuine null, not an underpowered shrug. A +0.6 pp gain would almost certainly have shown up. |
| **Primary test** | −0.16 pp [−0.39, +0.08], p = 0.19 | Not significant; CI comfortably contains 0. |
| **Novelty / primacy** | Cumulative lift settles near −0.16 pp within a few days and stays flat. | No decay or ramp — a longer test wouldn't change the call. |
| **Segments** (3 countries × 7 weekdays) | 3 slices flip sign vs the aggregate; Saturday −0.75 pp (raw p = 0.02) is the largest, **not significant after Bonferroni**. | No credible subgroup where the new page wins. |
| **Guardrail** | Page-delivery error rate 1.31% vs 1.33% (p = 0.56) — balanced. | The ~1.3% mis-delivery isn't concentrated in treatment, so it doesn't bias the arms. Note: the dataset has no engagement metric (time-on-page, bounce, AOV), so a true business guardrail can't be computed here. |

## Layout

```
src/experiment.py     all the statistics as plain, tested functions (no I/O, no plots)
src/run_analysis.py   headless pipeline: runs the 7 steps, writes charts + results.json
src/fetch_data.py     re-download the raw CSVs (also committed) with sha256 verification
tests/                synthetic-data unit tests per function + a frozen-value regression
                      test that replays the pipeline on the real data
data/raw/             ab_data.csv, countries.csv (committed)
data/processed/       results.json — frozen headline numbers the regression test checks
```

## Reproduce

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
make all          # runs src/run_analysis.py then the test suite
```

`make analysis` writes the five charts and `data/processed/results.json`;
`make test` runs 19 tests (~6 s), including the end-to-end check that the
committed headline numbers still reproduce.

## Notes and limits

- **Weak guardrail.** Instrumentation only. A real ship decision needs an
  engagement or revenue guardrail, which this dataset doesn't carry.
- **Observational segments.** Country and weekday cuts are exploratory and
  Bonferroni-corrected; treat any single-slice result as hypothesis, not finding.
- **Effect size framing.** "Underpowered for +0.6 pp" would be a different memo;
  this test is well-powered for that effect, which is what makes the null
  informative.
